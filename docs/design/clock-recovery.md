# 时钟恢复

启动会清除上一进程的时钟锚点，但保留已校准状态、日期高水位和当日记录。

RTC 的 VLF（振荡停止）表示日期数据不可信，必须重新校时。VBLF（VBAT 低电压检测）是锁存警告，写 0 清除；本项目在显式校时中尝试清除。其他日期、事务与有效性校验通过时，VBLF 本身不使读数无效，也不隐藏今日统计。VBLF 的原始状态保留在 `device_clock::Reading.lowVoltage` 供诊断使用。标志定义见 [Epson RX8130CE 手册](https://download.epsondevice.com/td/pdf/app/RX8130CE_en.pdf)的 Table 31 和 Table 41。

重启后第一次读到同一天或更新的日期时，恢复今日统计。以下情况仍记为异常：

- 日期低于已保存的日期高水位。
- 同一进程内，UTC 与单调时钟的偏差超过 120 秒。

异常状态下的步数只计入累计，不显示为今日步数。已保存的异常标记不会在启动时自动清除。普通校时选择同一天或更新的日期时直接恢复；选择更早日期时归档当前记录、开始新的计时段，并把所选日期作为新的今天。时区变更仍沿用原计时段。未知日期期间的步数不回填。

## 关机时间保持

双击电源键关机由 M5PM1 硬件执行，默认会切断给 RTC 与 IMU 供电的 L1，RTC 失电后按 VLF 规则要求重新校时。固件每次开机对 PM1 `HOLD_CFG(0x07)` 置 LDO 3.3V 电源保持位（读-改-写并回读），关机期间 L1 保持供电，RTC 继续走时，开机后时间连续。PM1 读、写或回读失败时打印一行诊断并按无保持的旧行为继续启动，不阻塞玩法；真实失时仍按上文规则处理。已有设备观察与未验证范围见[验证说明](../verification.md#设备观察与待验事项)。

## 烧录后校时

`scripts/flash.sh` 在应用启动后，通过 USB 串口以烧录电脑的当前 UTC 校时。已校准存档保留原时区；首次校准采用电脑当前时区偏移。设备运行时不需要网络，普通重启不写入新时间。同一固件再次烧录时也从电脑取得当次时间，不使用编译日期。

主机请求经过 Runtime 和 Engine 的既有事务：先保存待校时记录，再写 RTC 并验证，最后保存确认结果。只有最终存档提交成功且实际读数可信，才能向主机报告成功。读回状态与主机当前时间不符时，主机报错，不把“固件写入成功”当作“校时成功”。测试模式不接受正式硬件校时，活动流程与保存错误仍保留原来的保护。

校时沿用普通日期变更规则。同日校时保留今日步数；跨日归档旧日桶；回拨到更早日期开启新的计时段。已记在错误日期的步数不会移入今天，累计步数、伙伴与培养账户不因校时清零。

## 单独校时与查询

`scripts/flash.sh` 烧录后自动通过同一串口把设备校到主机当前时间。已校准设备保留存档时区；首次校准采用主机时区。校时须完成 RTC 回读和存档提交才报告成功，失败时脚本退出 3，此时固件已经写入，可单独重试校时：

```bash
rtk proxy mise exec -- python3 scripts/sync_clock.py --port /dev/cu.usbmodem1101
rtk proxy mise exec -- python3 scripts/sync_clock.py --port /dev/cu.usbmodem1101 --query
```

把示例端口换成目标设备的实际端口。`--query` 只读 RTC 和事务状态，并与主机当前 UTC 比较；超出 15 秒容差时非零退出。

诊断时可用 `rtk proxy mise exec -- ./scripts/flash.sh --no-sync <port>` 跳过校时；这不会纠正设备日期。烧录入口见 [README](../../README.md#构建和烧录)，校时与存档的设备验证边界见[验证说明](../verification.md#设备观察与待验事项)。

# 验证范围与已知限制

本文说明应运行的检查、各类证据能证明什么，以及仍开放的限制。命令和依赖见[开发指南](development.md#检查入口)，桌面操作见[模拟器指南](simulator.md)，E2E 场景见[覆盖矩阵](design/simulator-e2e-coverage.md)。硬件资料入口见 [StopWatch 开发资源](verification/stopwatch-c152-dev-resources.html)。

当前实现为全国图鉴 1～649、320 条进化边、五个世代地区、中英文界面、最多 32 场的遭遇队列、schema9、ruleVersion 3。“覆盖”仅描述测试范围，是否通过以本轮命令和产物为准。

测试仅保留产品／逻辑假设与构建发布保障，取舍见[测试保留标准](verification/test-policy.md)。不维护内部调用次数、对象布局、源码文本或整屏哈希等实现约束；相同假设优先保留观察结果最直接的一层。

## 每次任务的 E2E 验收要求

默认按影响范围选择专项检查和定向 E2E，不以“改了代码／测试／配置”“新增功能”或“准备提交 PR”作为全量触发条件。

| 改动 | 默认验收 |
| --- | --- |
| 文档、注释、说明截图等非行为改动 | 内容、链接和格式；不跑 E2E |
| 局部页面、绘制或动画 | 对应渲染套件并读图；交互变化再跑相关 `--case` |
| 单个玩法／输入／保存流程修复或新增功能 | 对应主机测试及受影响的 E2E 场景，覆盖失败与恢复分支 |
| 单场景测试、断言或截图采集 | 跑该场景；共享辅助函数再跑所有使用它的场景 |
| 局部构建配置、素材或生成器 | 相应构建／生成校验；影响运行时再补相关场景 |

**只有以下情况要求全量：**

1. 改变跨多个用户流程的共享状态机、事务提交／恢复语义、全局输入或时钟调度；已有定向场景不能覆盖其交叉影响。
2. 改变存档格式、迁移、CRC／语义校验或双槽存储协议，可能影响所有旧档或恢复路径。
3. 改变全局 E2E runner、场景注册／隔离、公共启动／事件注入，或确实影响全部模拟场景的依赖与环境配置。只调整 runner 中某个场景的证据采集不属于此项。
4. 用户明确要求完整回归，或已约定的发布验收明确要求全量。

全量前说明命中的条件及定向检查不足之处；影响范围不清时先查调用关系和覆盖矩阵，不以“保险起见”默认全量。满足条件后由主 agent 汇总改动，执行一次：

```bash
rtk proxy mise run test-simulator-e2e
```

- **新功能新增覆盖**：在 [test/simulator](../test/simulator) 新增场景或在已有场景中新增该功能的操作链与断言，并接入 [runner](../scripts/run_simulator_e2e.py) 的默认全量运行。仅运行已有测试不算为新功能补测；同步更新[覆盖矩阵](design/simulator-e2e-coverage.md)。
- **验证用户可观察的结果**：操作通过真实 SDL 输入进入 Runtime，断言页面与业务结果；涉及存档时验证真实文件和新进程恢复，涉及失败重试时验证不重复结算。UI 改动还须保留并读取真实渲染截图。仅硬件可验证的部分另列设备验收，不能由模拟器通过代替。
- **迭代使用定向检查**：按改动范围运行专项检查，必要时用 `--case` 或 `--suite core` 验证相关路径。不要每改一个文件、完成一个小步骤就运行全量 E2E。
- **全量统一协调**：只有命中上述条件时才安排全量，由主 agent 或指定的一个验收 agent 执行；子 agent 默认只做职责范围内的定向验证。未命中条件时，定向 E2E 可以作为本次交付验收；`--build-only` 不证明行为通过，`--suite core` 也不是全量。
- **有原因才重跑**：失败先排障并定向复测；修复后重新评估上述条件，局部修复可用定向结果关闭对应失败，记录此前全量中未受影响的结果，不把组合证据写成“最终全量通过”。后续改动只重验受影响范围，不因提交、文档或交接重跑；纯文档等非行为改动也不中断正在运行的验收。
- **以本轮证据报告结果**：使用新的验收目录，记录命令、退出状态、通过／失败场景和证据路径。测试失败、依赖缺失或环境阻塞时，明确报告未完成验收；未运行不能记为通过，也不能删除、跳过失败场景来满足交付条件。

仍须完成[相应专项检查](development.md#检查入口)、固件构建和必要的设备验收；纯文档不重建固件。下述 CI 自动触发不构成本地重复验收要求。

[GitHub Actions](../.github/workflows/simulator-e2e.yml) 对涉及非文档文件的 PR、`main` 推送和手动运行执行全量 E2E（纯文档、README、AGENTS、许可与声明改动通过 `paths-ignore` 跳过）。工作流缓存 PlatformIO／pip 依赖与 `.pio/host-build` 目标文件，并上传 PNG 截图、结果与测试存档，保留 7 天；具体步骤见[开发指南](development.md#github-actions)。是否通过以对应提交的 Actions 结果为准。

## 已知失败与限制

2026-10-31 曾修正两项渲染测试问题：旧战斗检查在绘制间隔内读到上一帧，测试模式菜单辅助操作的次数上限不足；当时的定向回归属于历史记录。2026-11-04 审计后，独立战斗渲染套件已删除，测试模式仍保留真实控制台操作链。历史通过结果不能代替本轮验收；当前 48 场 E2E 与 12 套渲染入口的状态以本次输出为准。

原 251 种、26 页三路线的独立 Pillow 历史设计画廊及失效预览脚本已退役清理，不再作为验收依据；实际页面覆盖与渲染检查入口见[UI 实现维护](design/ui-scene-redesign-implementation.md)。

其他限制：

- 首捕卡与最近捕捉详情中，部分物种的角色阴影压在“地区 · 累计捕捉 N 次”一行文字上；该问题早于五地区改动，尚未修正。
- RTC 待确认标记清除到最终确认之间仍存在非原子窗口。主机故障注入不能证明实际备电保持或物理断电安全。2026-11-07 设备再次报告 `rtc=0 low=0 io=0`，主机校时后恢复 `rtc=1 tr=1`；旧回执缺少具体失效原因，尚不能确认供电或振荡停止根因。新增的草稿提示、状态字段与初始化前寄存器日志不代表已消除硬件失时，仍需设备复发／掉电保持验证。
- 没有首次 LittleFS 格式化入口。挂载失败保留数据并限制玩法，不能自动格式化来消除错误。
- 本地验证使用 macOS；Ubuntu X11/Xvfb 的全量 E2E 以对应提交的 Actions 结果为准，Linux 真实桌面人工操作尚未验收。模拟器使用 POSIX 文件锁，不支持原生 Windows。端口自动探测仅支持 macOS，多个设备须显式指定端口。
- SDL 队列输入不证明原生 OS 键鼠注入；已有 macOS 检查记录未取得辅助功能和事件投递权限，原生输入尚未验收。
- Runtime/M5GFX/SDL 截图、像素比较与人工读图分别承担不同检查。关键截图抽查不代表全部图片已逐张审阅，Pillow 设计稿不能替代真实渲染证据。

## 设备观察与待验事项

历史设备观察及本地证据索引见[设备观察记录](device-observations.md)，适用范围仅为当时固件。

待验事项：

- 振动是否可感知。2026-11-02 对战和投球均无振感，参数与马达未测情况见[设备观察记录](device-observations.md)。软件侧已将触发强度与脉宽调整为分级档位（35/50/80 毫秒，强度 180/215/255）、新增新遭遇双脉冲提醒（65+50+85 毫秒，强度 255）并在存盘前停振；硬件马达在当前电源配置下的实际起振、体感标定、可辨识度，以及最近 2 秒有步数时停振是否漏步或误停仍为待验项。
- 电源键解锁重启已获用户确认修复，见[设备观察记录](device-observations.md)。USB／纯电池、主动／闲置熄屏及双击关机尚无逐项验收记录；USB 不进入 CPU 浅睡，不能替代纯电池覆盖。启动关闭 `output_power`（5V 升压）与 PM1 绿灯后，真机亮屏、振动、唤醒及口袋浅睡防误醒尚未实测。
- BMI270 50 Hz 低功耗配置（关陀螺仪／温度／辅助接口）下的四种携带方式计步误差；真实走路达到 200–500 步、捕获并保存的全过程；其余按键／触摸场景。
- 伙伴列表／战斗／投球页以外的 466×466 圆屏边缘，五地区在实体 AMOLED 上的色带与观感，CO5300 `DISPOFF`/`SLPIN` 熄屏与 `SLPOUT`/`DISPON` 唤醒观感、动画与唤醒时延；启动页的真机开机耗时、动画帧率与观感。
- 跨日关机 RTC 保持、真实失时、满盘与断电恢复、动态堆峰值、完整任务栈、采样间隔及四态（亮屏静止／亮屏动画／熄屏静止／熄屏步行）纯电池功耗。关机 LDO 同时供电 RTC 与 IMU（含 BMI270 关陀螺仪低功耗态）的续航代价未测。

## 生成和保留本轮证据

按[开发指南](development.md#检查入口)准备依赖。E2E 默认创建 `.pio/verification/` 下的新时间戳目录，`MYM5_VERIFICATION_DIR` 可指定尚不存在的目录。渲染、玩法、计步、RTC、校时和存储任务也支持该变量，应为每轮选择独立路径，避免覆盖。普通桌面模拟器的截图位于 `.simulator/screenshots/本次启动时间/`，不再另有 smoke 验收目录入口。

E2E 根目录的 `manifest.json` 记录仓库内实际参与编译的源码、依赖配置和可执行文件哈希及环境，`result.json` 汇总场景结果；每个启动阶段保留事件、业务快照、真实存档、PNG 截图和进程退出码。三种强杀场景的预期退出码为 SIGKILL（`-9`），必须连同新进程恢复断言判断，不能单看非零退出码。字段说明见[E2E 证据](design/simulator-e2e.md#执行与证据)。

需要命令日志时保存标准输出、标准错误和退出状态。重跑只验证当时源码与环境，不恢复已清理的历史证据。保留原始验收数据、Flash 备份及存档；新用户构建不依赖这些产物。

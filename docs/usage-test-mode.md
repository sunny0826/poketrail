## 设备内测试模式

测试模式供开发者和维护者复现问题，不属于普通玩法。测试进度使用独立存档，不合并回正式档；正式玩法仍使用 schema4／ruleVersion 3、每场 200–500 探索步和最多两次投球。

### 进入与返回控制台

1. 从主菜单打开“资源与数据”。正式档无法加载时，在存档错误页操作。
2. 在顶部标题区域按住至少 2 秒，再松手；不要同时按侧键。确认页显示“进入测试模式”和“正式存档不变”。
3. 选择“复制正式存档”或“空白测试档”并确认，也可选“返回”取消。正常进入前会先保存正式档中可提交的未落盘进度；保存失败时先完成重试。快照复制正式槽位的原始字节，后续迁移只作用于测试副本；坏档或不支持的版本仍会报错，需要从空白档开始。
4. 进入后打开测试控制台。首页、控制台、校时、图鉴和错误页等页面底部显示金色“测试”；进入图鉴不会退出测试模式。

控制台沿用菜单操作：左键上移、右键下移、双键确认，也可触摸和翻页。选择“返回”继续测试档中的玩法；需要重新打开控制台时，在“资源与数据”或测试存档错误页重复顶部长按。

### 使用测试控制台

| 入口 | 操作与结果 |
| --- | --- |
| 注入步数 | 选择 +1／+10／+100／+1000／+5000 步，按现有步数队列分批入账；测试档未就绪或存在待重试的保存时，不接受注入 |
| 日期与时间 | 沿用校时页面，选择字段、修改并“保存并校时”；只改变测试时钟，不写硬件 RTC |
| 构造状态 | 选择后立即替换并重新加载测试档：账户 2000 步／历史球库存 1 球、临近遭遇 299/300 步、规则 3 已用 1 球的待投球场、rule1 旧规则在途场；当前规则仍不受球库存限制 |
| 故障开关 | 选择“无故障”“写入前失败”“写入后失败”或“读取失败”；分别恢复正常、拒绝测试提交、写入后报告失败、拒绝后续测试加载 |
| 诊断 | 查看文件系统或 RAM-only 模式、schema、当前遭遇 rule、sequence、正式／测试槽位总字节数、容量、可用空间、故障和清理／初始化结果 |
| 重置测试档 | 在确认页选择“重新复制正式存档”或“重置为空档”；替换设备上的测试进度 |
| 退出测试模式 | 进入确认页，再选“确认退出”；丢弃测试进度并加载正式档 |

例如，复现当前规则的遭遇触发：先在“构造状态”选择“临近遭遇 · 299/300步”，再“注入步数”选择“+1 步”。回到测试玩法后可见待战遭遇，下一场目标仍在 200–500 步范围内。

故障选择作用于后续对应的存储调用，不会立刻重载当前页面。“写入后失败”可能已经写入测试槽，取消故障后应重试同一次结果。发生保存错误时，可从错误页长按顶部回控制台，选“无故障”后返回错误页重试，也可确认退出并丢弃测试进度。“读取失败”目前没有配套的设备内重载入口；其自动回归通过主机重建 Runtime 触发，不能靠设备重启复现，因为故障开关不会持久保存。

### 存储、重启与退出

存储可用时，测试槽位位于 `/adventure-test/`，模式标记为 `/adventure-test/active`；正式槽位仍在 `/adventure/`。正常重启按标记继续加载测试档，直到显式退出。退出先删除模式标记，再删除测试槽位与目录；测试数据清理失败仍切回正式模式，残留测试档不会被正式模式加载。若模式标记本身无法删除，则显示退出失败并继续保持测试模式。

只有文件系统未能挂载时，选择“空白测试档”才使用 RAM-only。此时不能复制正式快照，测试档和模式不跨重启保存，也不具备双槽或掉电保护；不会自动格式化文件系统。正式档损坏但文件系统可用时，空白测试档仍写入独立测试目录。

测试模式不消费真实 IMU 计步，走路不会增加测试步数；模拟日期与时间不写硬件 RTC，退出后恢复正式计步与 RTC 时间来源。测试数据不写回正式槽；进入前的正常保存仍可能更新正式档，退出加载不会提交启动记录或改变正式槽字节。当前不提供测试档导入／导出入口；完整验证边界见[Issue #7 验证记录](verification.md#issue-7-设备内测试模式2026-10-27)。
